# ML全般エラー修正Skill

機械学習全般の論文メモ作成時に発生しやすいエラーパターンを蓄積します。

## エラーカテゴリ

### 1. 実験設定の問題

#### 1.1 ランダムシードの未記載
- **症状**: 結果の分散、信頼区間の記載なし
- **修正**: シード数、標準偏差を記載
- **チェック**: 結果の再現性が評価できるか

#### 1.2 ハイパーパラメータ探索の不公平
- **症状**: 提案手法だけ入念にチューニング
- **修正**: ベースラインとのチューニング条件を比較記載
- **チェック**: 公平な比較になっているか

#### 1.3 早期停止の条件
- **症状**: いつ学習を止めたか不明
- **修正**: 早期停止の条件、検証セットの使い方を記載
- **参照メモ**: [[early-stopping]]

### 2. 最適化の問題

#### 2.1 オプティマイザの詳細欠落
- **症状**: 「Adamを使用」だけ
- **修正**: 学習率、weight decay、スケジューラを記載
- **参照メモ**: [[optimizers]]

#### 2.2 バッチサイズの影響
- **症状**: バッチサイズの選択理由なし
- **修正**: バッチサイズと性能の関係を確認
- **チェック**: スケーリング時の注意点が分かるか

### 3. データの問題

#### 3.1 データリークの可能性
- **症状**: train/test分割の詳細なし
- **修正**: 分割方法、時系列考慮の有無を記載
- **チェック**: リークの可能性を評価できるか

#### 3.2 データ不均衡への対処
- **症状**: クラス不均衡の扱いが不明
- **修正**: サンプリング手法、重み付けの有無を記載
- **参照メモ**: [[class-imbalance]]

### 4. 理論と実践のギャップ

#### 4.1 仮定の現実性
- **症状**: 理論的保証の仮定が現実的か不明
- **修正**: 仮定の現実性、違反時の影響を記載
- **チェック**: 実応用時の注意点が分かるか

#### 4.2 計算量の理論と実測
- **症状**: O(n)表記だけで実測なし
- **修正**: 理論計算量と実測時間を併記
- **参照メモ**: [[complexity-analysis]]

### 5. 連合学習・分散学習特有

#### 5.1 通信コストの記載
- **症状**: 精度だけで通信量の記載なし
- **修正**: 通信ラウンド数、転送データ量を記載
- **参照メモ**: [[federated-learning]]

#### 5.2 非IIDデータの扱い
- **症状**: データ分布の異質性への対処が不明
- **修正**: 非IID設定の詳細、対処法を記載
- **チェック**: 実環境での適用可能性が分かるか
