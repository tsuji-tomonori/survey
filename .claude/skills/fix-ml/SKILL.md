# ML全般エラー修正Skill

機械学習全般の論文メモ作成時に発生しやすいエラーパターンを蓄積します。

## エラーカテゴリ

### 1. 実験設定の問題

#### 1.1 ランダムシードの未記載
- **症状**: 結果の分散、信頼区間の記載なし
- **修正**: シード数、標準偏差を記載
- **チェック**: 結果の再現性が評価できるか

#### 1.2 ハイパーパラメータ探索の不公平
- **症状**: 提案手法だけ入念にチューニング
- **修正**: ベースラインとのチューニング条件を比較記載
- **チェック**: 公平な比較になっているか

#### 1.3 早期停止の条件
- **症状**: いつ学習を止めたか不明
- **修正**: 早期停止の条件、検証セットの使い方を記載
- **参照メモ**: [[early-stopping]]

### 2. 最適化の問題

#### 2.1 オプティマイザの詳細欠落
- **症状**: 「Adamを使用」だけ
- **修正**: 学習率、weight decay、スケジューラを記載
- **参照メモ**: [[optimizers]]

#### 2.2 バッチサイズの影響
- **症状**: バッチサイズの選択理由なし
- **修正**: バッチサイズと性能の関係を確認
- **チェック**: スケーリング時の注意点が分かるか

### 3. データの問題

#### 3.1 データリークの可能性
- **症状**: train/test分割の詳細なし
- **修正**: 分割方法、時系列考慮の有無を記載
- **チェック**: リークの可能性を評価できるか

#### 3.2 データ不均衡への対処
- **症状**: クラス不均衡の扱いが不明
- **修正**: サンプリング手法、重み付けの有無を記載
- **参照メモ**: [[class-imbalance]]

### 4. 理論と実践のギャップ

#### 4.1 仮定の現実性
- **症状**: 理論的保証の仮定が現実的か不明
- **修正**: 仮定の現実性、違反時の影響を記載
- **チェック**: 実応用時の注意点が分かるか

#### 4.2 計算量の理論と実測
- **症状**: O(n)表記だけで実測なし
- **修正**: 理論計算量と実測時間を併記
- **参照メモ**: [[complexity-analysis]]

### 5. 連合学習・分散学習特有

#### 5.1 通信コストの記載
- **症状**: 精度だけで通信量の記載なし
- **修正**: 通信ラウンド数、転送データ量を記載
- **参照メモ**: [[federated-learning]]

#### 5.2 非IIDデータの扱い
- **症状**: データ分布の異質性への対処が不明
- **修正**: 非IID設定の詳細、対処法を記載
- **チェック**: 実環境での適用可能性が分かるか

### 6. 量子機械学習・理論MLの問題

#### 6.1 理論的保証の確率的性質
- **症状**: PAC学習等の確率的保証を「絶対的な保証」と誤解
- **修正**: 「確率1-δで」「εの精度で」等の条件を明記し、tightでない境界の場合は限界を記載
- **チェック**: 理論的保証が破れる条件（大データ、高性能モデル等）を認識できるか
- **参照論文**: [[P-2501.00754_v1]]

#### 6.2 物理的インフラの前提
- **症状**: 量子通信等の物理インフラ要件が不明
- **修正**: 実用化に必要な物理インフラ、現状の成熟度を記載
- **チェック**: 短期・長期の実用性評価ができるか
- **参照論文**: [[P-2501.00754_v1]]（量子チャネルCQ前提）

#### 6.3 実験と理論の乖離
- **症状**: 理論予測と実験結果の差異への言及なし
- **修正**: 理論予測からの逸脱がある場合、その条件と原因（ヒューリスティックな性質等）を記載
- **チェック**: 理論の適用範囲を理解できるか
- **参照論文**: [[P-2501.00754_v1]]（大データ・高性能モデルで理論から逸脱）

#### 6.4 専門用語の説明不足
- **症状**: PAC学習、no-cloning定理等の専門用語を説明なしに使用
- **修正**: 初出時に括弧書きで簡潔な定義を追加（例: 「PAC学習: 高い確率で近似的に正しい仮説を学習する理論的枠組み」）
- **チェック**: 量子・理論ML分野外の読者も理解できるか
- **参照論文**: [[P-2501.00754_v1]]
