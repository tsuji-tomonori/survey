# 論文読解・要約Skill

## 概要

このSkillは、arXiv論文を体系的に読み解き、Obsidian Vaultに高品質な知識ベースを構築するためのガイドラインです。

## 1. 読む前のゲート（最初の3分）

### 論文タイプ判定

論文タイプによって読み方が変わる。以下から判定：

| タイプ | 特徴 | 重点確認箇所 |
|--------|------|-------------|
| method paper | 新手法提案 | Method, Ablation |
| benchmark | 実験比較 | Setup, Baselines |
| survey | 俯瞰 | Related work, 分類 |
| theory | 理論証明 | 定理, 仮定 |
| systems | 実装・最適化 | 設計, スケーラビリティ |
| application | 応用事例 | ドメイン適合, 実用性 |

### 読む価値の見積もり

- **新規性の種類**: アルゴリズム / 目的関数 / データ / 評価軸 / スケール / 実装
- **自分の目的との関連**: 直接使える / 理解すべき潮流 / 参考程度

### 版管理チェック

- `updated` フィールドとPDFの版が一致しているか確認
- v2以降で実験が差し替えられている可能性に注意

## 2. Problem / Setting（最重要）

**要約全体の品質を決めるセクション**。以下を必ず明確化：

| 項目 | 確認内容 |
|------|----------|
| 入力/出力 | 何を与えて何を返すか |
| 目的 | 最適化するもの、達成したい性質 |
| 評価 | どの指標で良いとするか |
| 制約 | 計算資源、データ入手性、推論時制約 |
| 比較対象 | 誰がライバルか、どの系譜か |

**チェック**: "我々はXを改善する" が **何の条件下で** かを書けているか

## 3. Key Contributions（証拠付きの差分）

以下の粒度で記載：

```
- [提案内容]: [既存手法との差分（1文）] → [根拠となる実験/分析]
```

**避けるべき書き方**:
- 「性能が向上した」だけ（条件・指標・比較対象が不明）
- "first/novel/SOTA" をそのまま転写（誇張混入リスク）

## 4. Method（再現可能な最小単位）

確認・記録すべき最小セット：

1. **前処理/入出力表現**: tokenization, feature, prompting形式
2. **モデル/アルゴリズムのコア**: 数式 or 擬似コードの要点
3. **学習手順**: データ, 損失, 最適化, ハイパラ, スケジュール
4. **推論手順**: 生成/検索/サンプリング/デコード, 計算量
5. **追加要素**: 蒸留, RLAIF, LoRA, 量子化等

**落とし穴**: 推論時手順が抜けて再現不能になりがち

## 5. Experiments（公正性・再現性チェック）

確認順序：

1. **Dataset/Benchmark**: 版, フィルタ, 分割（train/test leak確認）
2. **Metrics**: 指標が目的と一致しているか
3. **Baselines**: 最強ベースラインの有無、設定の最新性
4. **Setup**: モデルサイズ, 学習時間, データ量, 推論コスト

**公正性チェック**:
- [ ] 同等計算量（FLOPs, steps, wall-clock）で比較か
- [ ] 追加データ・外部ツールの有無
- [ ] ハイパラ探索の差（提案法だけ手厚くないか）

## 6. Results（数字＋意味＋条件）

記載テンプレート：
```
[指標]で[ベースライン]に対して[差分]: 条件（データ/モデル/計算量）
例: "GLUE平均で +1.2、同パラメータ規模、同データ量条件"
```

**必須項目**:
- 絶対値と差分の両方
- 可能なら分散/信頼区間、少なくともseed数

## 7. Ablations / Analysis

記録すべき知見：
- どのコンポーネントが効いたか
- どの条件で効かないか（失敗例, 分布外, 長文, 低資源）
- スケール則（モデルサイズ/データ量/コンテキスト長での傾向）

**注意**: アブレーション不十分な場合は `risks` に記載

## 8. Limitations / Risks（使うときの地雷マップ）

以下を厳しくチェック：

| カテゴリ | 確認項目 |
|----------|----------|
| 再現性 | コード有無, 詳細記載, データ公開, パラメータ |
| 外的妥当性 | 特定ベンチのみ成立, 実運用データで不明 |
| 計算コスト | 学習/推論コストの現実性 |
| 安全性/倫理 | バイアス, プライバシー, 悪用可能性 |
| 評価の穴 | ベースライン不備, データリーク, 指標不適 |

## 9. プロパティ運用ガイド

### methods / tasks / datasets

- 本文の言い回しではなく **統一語彙** で入力
- 迷ったら広い語彙を優先（例: `retrieval`, `transformer`）
- 詳細はTopicノートで補完

### claims / risks

- **claims**: 主張を短文で（できれば定量）
- **risks**: 反証・制約を短文で（根拠付き）

## 10. 読み方の優先順位（時間がないとき）

1. Abstract + Figure 1 + Conclusions（全体像）
2. Setting / Data / Evaluation（前提と妥当性）
3. Main results table（数字）
4. Methodのコア（何が新しいか）
5. Ablations / Limitations（信用できるか）
6. Related work（位置づけ）

## 11. 品質チェックリスト

論文メモ作成後、以下を確認：

- [ ] タスク設定（入力/出力/評価/制約）を1段落で書ける
- [ ] 既存手法との差分を1文で書ける
- [ ] 主要結果は "絶対値＋差分＋条件" が揃っている
- [ ] ベースラインの公正性を確認した
- [ ] 再現に必要な情報の有無を判断した
- [ ] 限界/リスクを「使うときの地雷」として書いた

## 12. エンティティ連携

論文読解時、以下のエンティティも更新：

### Methods（03_Entities/Methods/）
- 新規手法が登場したら `/update-method {手法名}` で作成/更新
- 既存メソッドへの改良の場合はリンク追加
- 例: `/update-method transformer`, `/update-method gradient-compression`

### Datasets（03_Entities/Datasets/）
- 新規データセットは `/update-dataset {データセット名}` で作成
- 既存の場合は使用論文リストに追加
- 例: `/update-dataset ImageNet`, `/update-dataset GLUE`

### Topics（02_Topics/）
- 論文がカバーするトピックへ `/update-topic {トピック名}` でリンク
- 新規トピックは作成を検討
- 例: `/update-topic federated-learning`, `/update-topic large-language-models`

### Authors（03_Entities/Authors/）
- 重要著者（2回以上登場）は `/update-author {著者名}` で作成
- 例: `/update-author Yoshua-Bengio`

## 使用方法

このSkillは `/read` コマンドと連携して使用します。
