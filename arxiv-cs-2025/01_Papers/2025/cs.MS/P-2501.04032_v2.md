# TL;DR（3行）
- Collatz数列の停止時間を計算する新アルゴリズムを提案
- Collatzツリーの構造パターンを利用し、偶数処理時に最大2のべき乗で一括削減
- 既存手法比で約28%の反復回数削減、計算量O(log n)を達成

# Problem / Setting
- 入力/出力: 正整数n → 全停止時間（total stopping time: nが1に到達するまでのステップ数）
- 目的: Collatz数列の停止時間計算の高速化
- 評価指標: 反復回数（iterations）、実行時間
- 制約: メモ化・並列化を使用しない単純なアルゴリズム
- 比較対象: Ren et al. (2018)のcode word方式、ビット演算ベースの素朴実装

# Key Contributions
- [Collatzツリー構造の活用]: 偶数処理時にn ∧ -n（ビットAND演算。最下位の1ビット位置を取得し、2のべき乗に対応）で最大2のべき乗を一度に取得 → 約28%反復削減
  - Collatzツリー: 各ノードnに対し、子ノードが2n（偶数経由）とpotentially (n-1)/3（奇数経由）で構成される木構造
- [計算量の理論的解析]: 平均O(4.65 log₂n - 4.91)、最悪O(28 log₂n - 180.17)を実験的に導出
- [大規模検証]: 2^100000〜2^100000+100000の範囲で停止時間計算に成功

# Method
- 前処理: なし（入力をそのまま処理）
- コアアルゴリズム:
  - 奇数n: n ← 3n + 1（1反復）
  - 偶数n: largest_power = n ∧ -n、n ← n / largest_power（log₂(largest_power)反復分を一括カウント）
  - n = 1で終了
- 学習手順: なし（数学的アルゴリズム）
- 推論手順: 上記ループを実行、空間計算量O(1)

# Experiments
- Dataset / Benchmark: 2^n - 1形式の数（n=100〜100000）、ランダム数、2のべき乗、3の倍数、素数
- Metrics: 反復回数、実行時間（ミリ秒）
- Baselines: Ren et al. [2]のcode word方式、ビット演算brute-force [3]
- Setup: MacBook Air M2 8GB (Python 3.12.4, Julia 1.11.2)、Google Colab NVIDIA T4 GPU

# Results（主要数値）
- 反復回数: 全入力サイズで約28%削減（例: 2^100-1で1465→1056反復）
- 実行時間: 小〜大ランダム数、2のべき乗、3の倍数、素数で一貫して高速
- 停止時間の正確性: 10億個の数でbrute-force実装と完全一致を確認

# Ablations / Analysis
- 効いたコンポーネント: 偶数処理時の一括削減（n ∧ -nによる最大2のべき乗取得）
- 反復回数の分布: 入力サイズに対して対数的増加（Table 1）
- 最良ケース: 2のべき乗（k=0、1反復）
- 最悪ケース: 多くのサブブランチを持つ数（log n比例）

# Limitations / Risks
- 再現性: コード非公開（アルゴリズムは疑似コードで記載）
- 外的妥当性: Collatz予想の証明には寄与せず、検証のみ
- 計算コスト: 極めて大きな数では任意精度演算が必要
- 評価の穴: 実行時間比較はマシン依存、反復回数と実行時間の関係は環境による

# Relation to Prior Work
- Ren et al. (2018): code word方式で2^100000-1まで検証、しかし計算量はO(L_seq)で本手法より劣る
- Venkatesulu & Parameswari (2020): ビット演算による素朴実装、同じく計算量O(L_seq)
- 本手法: Collatzツリーの構造を利用し、反復回数をO(log n)に削減
