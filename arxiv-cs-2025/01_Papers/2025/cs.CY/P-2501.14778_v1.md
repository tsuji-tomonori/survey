# TL;DR（3行）
- AI事故報告の現状を分析し、既存データベース（AIID, AIAAIC）の9つのギャップを特定
- 定義・分類の不統一、データ共有プロトコルの欠如、地理的・セクター的偏りなどの問題を指摘
- 標準化推進のための9つの提言を提示し、UN SDGs達成に向けた信頼性あるAI展開を目指す

# Problem / Setting
- 入力/出力: 既存AI事故データベースの構造・内容 → ギャップ分析と標準化推奨事項
- 目的: AI事故報告の標準化を推進し、将来の事故予防と信頼性あるAI展開に貢献
- 評価指標: ギャップの特定数、推奨事項の網羅性（定性的評価）
- 制約: オープンアクセスのデータベースのみを分析対象（AIID, AIAAIC）
- 比較対象: 航空業界・サイバーセキュリティの事故報告プロトコル

# Key Contributions
- [9つのギャップ特定]: 既存AI事故報告の体系的分析 → Table 10に整理
  - G1: 事故定義の不統一、G2: 分類体系の欠如、G3: 信頼性検証プロセスの不在
  - G4: データ共有プロトコルの欠如、G5: 投稿者の偏り、G6: 情報源の偏り
  - G7: 地理的偏り、G8: セクター偏り、G9: AIライフサイクル統合の欠如
- [9つの標準化推奨事項]: 各ギャップに対応する具体的アクション
  - R1: 統一定義策定、R2: ISO/IEC等の既存分類との整合、R3: ピアレビュー機構
  - R4: 相互運用可能なデータ交換形式、R5: 自動報告システム、R6: 多言語対応
  - R7: 地域別ハブ設置、R8: 重要セクター優先、R9: 開発フェーズ別報告項目
  - 実施主体: ITU、ISO/IEC、各国規制当局、AI開発企業
- [AIライフサイクルへの統合]: 事故報告をAI開発・運用の標準プロセスに組み込む概念図（Figure 1）

# Method
- 文献レビュー: AI事故リポジトリの網羅的調査
- データベース選定: AIAAIC, AIID, AILD, AVIDから、オープンアクセスの2つ（AIID, AIAAIC）を詳細分析
- 分析手法:
  - 報告ポリシー・スコープ・レビュー機構の比較
  - 実際に事故を投稿して報告プロトコルを検証
  - データフィールドの互換性分析（Table 3）
  - 投稿者・ソース・セクター・地域のカバレッジ分析

# Experiments
- Dataset / Benchmark: AIID（AI Incident Database, 657件）、AIAAIC（AI, Algorithmic, and Automation Incidents and Controversies Repository, 905件）（2024年5月時点）
- Metrics: 定性的分析（ギャップの有無、カバレッジの偏り）
- Baselines: 航空・サイバーセキュリティの事故報告体制
- Setup: 2024年のグローバル事故をフィルタして詳細分析

# Results（主要数値）
- **投稿者集中**: AIID上位4名で50%以上の事故を報告（Table 4）
- **ソース偏り**: 上位7ドメインは全て欧米メディア（Guardian, Verge, NYT等）（Table 5）
- **地域偏り**: AIAAIC事故の60%が3カ国（USA 46.9%, UK 6.5%, China 5.9%）（Table 8）
- **セクター偏り**: メディア/エンタメ 21.3%、自動車 9.5%、政治 8.3%（Table 6）
- **データ互換性**: 2データベース間で共通フィールドは6項目のみ（Table 3）

# Ablations / Analysis
- 効いた観点: 実際の事故投稿による報告プロトコルの実証的検証
- 限界条件: 著作権・倫理問題（AIAAIC1449, 1439）がAI事故定義に合致するか曖昧

# Limitations / Risks
- 再現性: 分析手法は記述されているが、詳細な基準は不明確
- 外的妥当性: 2つのデータベースのみの分析で一般化に限界
- 計算コスト: N/A（政策分析論文）
- 評価の穴: 推奨事項の実効性・実現可能性の検証なし、コスト・リソース見積もりなし

# My Notes（解釈・疑問・使い道）
