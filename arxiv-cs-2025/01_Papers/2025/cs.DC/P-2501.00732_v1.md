# TL;DR（3行）
- 無線トラフィック予測のための連合学習において、勾配スパース化による通信効率化と勾配相関に基づく個別化集約戦略を提案
- Error FeedbackとGradient Trackingで圧縮による性能劣化を補償し、3種類の相関ベース集約（k-relevant, δ-threshold, all-correlated）でクライアント間の空間的依存関係を捕捉
- 通信量を最大約40分の1（FedAvg比）に削減しながら、SOTAを上回る予測精度を実現

# Problem / Setting
- 5G/6Gネットワークにおけるエッジでの無線トラフィック予測は、自己最適化やネットワーク管理に不可欠
- 従来のFLベース手法は生データ送信を回避するがモデル更新のための勾配通信オーバーヘッドが大きい
- 分散自律ネットワーク（DAN）のSmall Cloud Unit（SCU）間で空間的依存関係をFLフレームワーク内でモデル化する方法が未解決
- 異なるトラフィックパターンを持つクライアントの勾配を単純平均すると性能が劣化する問題

# Key Contributions
- 無線トラフィック予測に勾配スパース化を初めて導入し、通信オーバーヘッドを大幅削減
- Error FeedbackとGradient Tracking技術で圧縮による負の影響を補償
- 勾配相関行列に基づく3つの個別化集約戦略（k-relevant, δ-threshold, all-correlated）を提案し、クライアント間の空間的依存関係を捕捉

# Method
- **勾配スパース化**: 圧縮率γに基づき、絶対値上位γ%の勾配要素のみを送信
- **Error Feedback**: フィルタリングされた勾配情報を蓄積し、次ラウンドで補償（e^m_{t+1} = e^m_t + g^m_t - φ(g^m_t)）
- **Gradient Tracking**: ローカル勾配方向とグローバル勾配方向の差分を追跡（h^m_{t+1} = h^m_t + 1/τ(φ(g^m_t) - g_t)）
- **個別化集約戦略**:
  - k-relevant: 相関係数上位kクライアントの勾配を集約
  - δ-threshold: 相関係数がδ以上のクライアントのみ集約
  - all-correlated: softmax重み付けで全クライアント勾配を加重平均
- モデル: 3層MLP（128-128-1）、スライディングウィンドウp=6（1時間分のトラフィックで次の10分を予測）

# Experiments
- Dataset / Benchmark: Milan CDR（4,222 BS, 88 SCU）, Trentino CDR（1,466 BS, 223 SCU）- Telecom Italia提供、2013年11月〜2014年1月の10分間隔データ
- Metrics: RMSE, MAE, R²スコア, 通信量ΔC (MB)
- Baselines: FedAvg, FedProx, FedAtt, FedDA, FedCOMGATE
- Setup: 200通信ラウンド、ローカル更新5ステップ、バッチサイズ20、圧縮率0.01、学習率ε=0.1（サーバー側η=1.0）、7週間を学習、残りをテスト

# Results（主要数値）
- **Milan**: 提案手法（k-relevant）がRMSE 0.1299, MAE 0.0788, R² 0.9501で最高性能
- **Trentino**: 提案手法がRMSE 0.6935, MAE 0.3621（k-relevant）、R² 0.9499（all-correlated）で最高性能
- **通信量**: 提案手法は3.15MB/7.58MB（Milan/Trentino）、FedAvgの126.27MB/322.68MBに対し約40倍効率的
- FedCOMGATE（14.37MB/38.45MB）と比較しても約4-5倍効率的
- 同じ損失達成に必要な通信量: FedAvg 30MB以上 vs 提案手法 3-13MB（γ依存）

# Ablations / Analysis
- **圧縮率γ**: 0.01→0.1で性能向上、0.1以上では改善頭打ち
- **集約クライアント数k**: k=3-4が最適、多すぎても少なすぎても性能低下
- **閾値δ**: δ=0.5-0.6が最適
- **入力長p**: p=6（1時間）が最適、短すぎると関係性捕捉不足、長すぎるとノイズ増加
- **ローカル更新回数τ**: τ=5-6が最適、大きすぎると収束悪化
- **バッチサイズ**: 20-30が最適

# Limitations / Risks
- ハイパーパラメータ（γ, k, δ, τ）のチューニングが必要でグリッドサーチ推奨
- 学習初期はFedAvgより損失が大きい（50ラウンド程度まで）
- 相関計算のためサーバー側で追加計算コストが発生
- 実験は2013-2014年のデータで、現代のトラフィックパターンへの適用性は要検証

# Relation to Prior Work
- **FedAvg**: 単純平均でデータ異質性に弱い → 相関ベース集約で改善
- **FedProx**: Proximal項追加だが通信量削減なし
- **FedAtt**: ユークリッド距離ベースの重み付けだが勾配相関は未考慮
- **FedDA**: Dual-attention + データ拡張だが追加通信が必要
- **FedCOMGATE**: 勾配圧縮の理論保証あるが個別化集約なし → 提案手法は両方を統合
