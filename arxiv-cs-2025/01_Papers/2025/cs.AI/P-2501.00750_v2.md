# TL;DR（3行）
- No-Codeプラットフォーム「Flowise」を用いて、マルチモーダルLLMベースのマルチエージェントシステム（MAS）を実装
- 画像分析→コード生成、Advanced RAG検索、画像生成、動画生成の4つのビジネスユースケースを提示
- 専門開発者なしでAI技術を企業に導入できることを実証（ただし定量評価なし）

# Problem / Setting
- 入力/出力: テキスト、画像、音声 → テキスト、コード、画像、動画
- 目的: 企業のAI技術導入における技術的複雑さ・コストの障壁を下げる
- 評価指標: 定性的評価のみ（ユースケースの実装可能性を実証）
- 制約: No-Codeプラットフォームの機能制限内での実装
- 比較対象: 従来のコーディングベースのMAS実装（暗黙的）

# Key Contributions
- [No-Code MAS実装方法論]: Flowiseを用いたSupervisor-Worker階層構造のMAS設計手法 → 4つのユースケースで実装を実証
- [マルチモーダル統合]: テキスト・画像・音声の入力とテキスト・画像・動画の出力を単一システムで処理 → 統合UIで動作確認
- [Advanced RAG + Web Search]: RAGで回答が見つからない場合にWeb検索エージェントにフォールバック → より正確な回答を提供

# Method
- 前処理: 音声入力はGPT-Whisperでテキスト変換、画像はOCRでテキスト抽出
- コアアーキテクチャ:
  - 4層構造: Multimodal Input Layer → Multi-Agent Layer → Process Layer → Multimodal Output Layer
  - Supervisor Agent: タスク分配、優先度設定、エラー管理を担当
  - Worker Agents: RAG検索、Web検索、画像分析、画像生成、動画生成の専門エージェント
- 使用モデル:
  - MLLM: OpenAI GPT-4o（画像理解・テキスト生成）
  - 画像生成: Stable Diffusion 3.5 large turbo（Replicate API経由）
  - 動画生成: Luma AI Ray model（Replicate API経由）
  - 音声認識: OpenAI Whisper
  - Embedding: text-embedding-ada-002
- 推論手順: ユーザー入力 → Supervisorがタスク分析 → 適切なWorkerに割り当て → 結果をSupervisorが統合

# Experiments
- Dataset / Benchmark: なし（ユースケースベースの実装デモのみ）
- Metrics: 定性的評価のみ（「効率向上」「精度向上」「時間短縮」と記載されるが数値なし）
- Baselines: なし
- Setup:
  - プラットフォーム: Flowise（Node.js + TypeScript）
  - ベクトルDB: In-Memory Vector Store
  - テキスト分割: Recursive Character Text Splitter
  - UI: Web-based chat interface

# Results（主要数値）
- 定量的結果なし
- ユースケース実装の成功を定性的に報告:
  1. 手書きコード画像 → Senior Programmer Agent → Quality Assurance Agent → 完成コード
  2. テキスト/音声クエリ → RAG検索 → (見つからない場合) Web検索 → 回答
  3. テキスト/スケッチ画像 → Stable Diffusion → 画像生成
  4. テキスト/画像 → Luma Ray → 動画生成

# Ablations / Analysis
- 各エージェントの役割分担の有効性を示唆（Senior Programmer + QA Engineerの協調など）
- Advanced RAG: RAGで回答がない場合のWeb検索フォールバックが有効
- 定量的なアブレーションは未実施

# Limitations / Risks
- 再現性:
  - 商用API（OpenAI、Replicate）に依存、コスト・可用性の問題
  - コードやワークフロー定義の公開なし
- 外的妥当性:
  - 定量評価なし、ベースラインとの比較なし
  - 特定ユースケースの実装デモに限定
- 計算コスト: APIコストの詳細記載なし
- 評価の穴:
  - 精度・レイテンシ・スケーラビリティの数値なし
  - ユーザー評価やA/Bテストなし
  - No-Codeプラットフォームの制約で複雑なカスタマイズ困難と著者自身が認識
- システム評価の欠如:
  - 複数エージェント間の通信オーバーヘッド未測定
  - 同時リクエスト処理時のスケーラビリティ未検証
  - API呼び出し回数・コストの定量分析なし

# Evidence / Recommended Reading（正当性の裏付け・次に読むべき論文）
> ※本論文の「Flowise上での実装」そのものを直接検証した論文は見当たらないため、ここでは**主張を支える基盤技術**（MAS/RAG/MLLM/生成モデル）の代表論文を整理。

## Multi-Agent Systems（Supervisor-Worker型の設計根拠）
- AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation (Wu et al., 2023, arXiv:2308.08155)
  - 複数エージェントの役割分担・協調が有効であることを示す基盤研究
- CAMEL: Communicative Agents for “Mind” Exploration of LLMs (Li et al., 2023, arXiv:2303.17760)
  - 役割分担型の対話エージェント設計がタスク解決に寄与
- MetaGPT: Meta Programming for Multi-Agent Collaborative Code Generation (Hong et al., 2023, arXiv:2308.00352)
  - Senior/QA/PMなどのロール分離によりコード品質改善を報告

## RAG + Web Search（Advanced RAG/フォールバックの根拠）
- Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks (Lewis et al., 2020, arXiv:2005.11401)
  - RAGの基本原理と効果を提示
- Self-RAG: Learning to Retrieve, Generate, and Critique (Asai et al., 2023, arXiv:2310.11511)
  - 取得→生成→自己批評の枠組みで回答精度向上
- Atlas: Few-shot Learning with Retrieval Augmented Language Models (Izacard et al., 2022, arXiv:2208.03299)
  - RAGによる少数ショット性能向上を体系的に評価

## Multimodal LLM（画像/音声入力→テキスト出力の根拠）
- Flamingo: a Visual Language Model for Few-Shot Learning (Alayrac et al., 2022, arXiv:2204.14198)
  - 画像＋テキスト入力を統合するMLLMの先行研究
- BLIP-2: Bootstrapping Language-Image Pre-training (Li et al., 2023, arXiv:2301.12597)
  - 画像理解とテキスト生成を統合する代表的モデル

## Image / Video Generation（画像/動画生成の根拠）
- High-Resolution Image Synthesis with Latent Diffusion Models (Rombach et al., 2022, arXiv:2112.10752)
  - Stable Diffusion系モデルの基盤論文
- Imagen Video: High Definition Video Generation with Diffusion Models (Ho et al., 2022, arXiv:2210.02303)
  - テキストから動画生成の代表的アプローチ
- Make-A-Video: Text-to-Video Generation without Text-Video Data (Singer et al., 2022, arXiv:2209.14792)
  - テキストから動画生成の先行研究
